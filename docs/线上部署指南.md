# ApiStation FinOps 线上部署指南

本文适用于当前版本的 ApiStation FinOps。

当前业务约束：

- 用户充值和余额扣减均使用 CNY/RMB。
- 用户侧只支持按量计费，`SUBSCRIPTIONS_ENABLED=false`。
- FinOps 只读访问 ApiStation 源表，不修改源系统用户余额、支付订单或用量记录。
- FinOps 只在自己的 `finops` Schema 写入账本、聚合、成本和对账数据。

## 一、部署前确认

在代码目录执行：

```powershell
pnpm install
pnpm test
pnpm check
```

生产迁移会自动按文件名顺序执行。迁移账号不应拥有数据库级 `CREATE` 权限；
部署授权脚本必须先由数据库管理员创建并授权独立的 `finops` Schema：

```text
001_init.sql
002_cny_accounting.sql
003_reconciliation_snapshots.sql
```

`002_cny_accounting` 只允许用于新的空 FinOps 账本。如果数据库中已经存在旧版
`002_dual_ledger`，或已有旧账本数据，迁移脚本会拒绝继续。不要直接把旧 USD Credit
数据批量改名为 CNY。

## 二、本地启动

### 2.1 演示模式

不设置 `DATABASE_URL` 时，服务自动使用演示数据，不连接线上数据库：

```powershell
pnpm install
pnpm start
```

浏览器打开 `http://127.0.0.1:8090`。

演示模式适合检查页面和交互，不代表线上真实数据已经接入。

### 2.2 连接测试数据库

```powershell
Copy-Item .env.example .env
```

至少填写：

```dotenv
NODE_ENV=development
DATABASE_URL=postgres://finops_app:密码@数据库地址:5432/YOUR_DATABASE_NAME
AUTH_DISABLED=true
BASE_CURRENCY=CNY
BILLING_UNIT=CNY
SOURCE_BALANCE_UNIT=CNY
SUBSCRIPTIONS_ENABLED=false
TIMEZONE=Asia/Shanghai
```

执行：

```powershell
pnpm preflight
pnpm migrate
pnpm backfill
pnpm start
```

## 三、接入线上真实数据

### 3.1 数据库结构

推荐 FinOps 与 ApiStation 共用同一个 PostgreSQL 数据库，但使用独立 Schema：

```text
源系统：public
FinOps：finops
安全配置视图：finops_source.balance_recharge_multiplier
应用角色：finops_app
```

不要让 FinOps 使用 PostgreSQL 管理员、ApiStation 主应用账号或可以读取账号凭证的账号。

### 3.2 创建最小权限账号

在服务器上使用 PostgreSQL 管理员：

1. 打开 `deploy/postgres-grants.sql`。
2. 将 `CHANGE_ME_BEFORE_RUNNING` 改为强随机密码。
3. 如果数据库名称不是 `YOUR_DATABASE_NAME`，同步修改 `GRANT CONNECT ON DATABASE ...`。
4. 执行：

```bash
psql -h 127.0.0.1 -U postgres -d YOUR_DATABASE_NAME \
  -f deploy/postgres-grants.sql
```

权限脚本会：

- 创建或复用 `finops_app`。
- 只授予同步所需源字段的读取权限。
- 禁止读取 `accounts.credentials`。
- 禁止读取 `public.settings` 的 `key/value`。
- 只通过安全视图读取 `BALANCE_RECHARGE_MULTIPLIER`。
- 允许 `finops_app` 写入自己的 `finops` Schema。
- 对不存在的订阅表和订阅字段使用兼容处理。

### 3.3 配置生产环境

在仓库根目录创建服务器专用 `.env`，不要提交到 Git：

```dotenv
NODE_ENV=production
HOST=0.0.0.0
PORT=8090

DATABASE_URL=postgres://finops_app:强随机密码@postgres主机:5432/YOUR_DATABASE_NAME?sslmode=disable
FINOPS_SCHEMA=finops
SOURCE_SCHEMA=public
SOURCE_SETTINGS_SCHEMA=finops_source

SYNC_ENABLED=true
SYNC_INTERVAL_SECONDS=60
SYNC_BATCH_SIZE=1000
SYNC_MAX_BATCHES_PER_CYCLE=3
SYNC_LOOKBACK_SECONDS=600
SUBSCRIPTIONS_ENABLED=false

BASE_CURRENCY=CNY
BILLING_UNIT=CNY
SOURCE_BALANCE_UNIT=CNY
TIMEZONE=Asia/Shanghai

AUTH_DISABLED=false
SUB2API_AUTH_URL=http://127.0.0.1:8080
SUB2API_AUTH_TIMEOUT_MS=10000
SESSION_SECRET=至少32位的随机会话密钥
SESSION_TTL_SECONDS=43200
SESSION_COOKIE_SECURE=true

APISTATION_DOCKER_NETWORK=现有的ApiStation网络名
FINOPS_PORT=8090
```

注意：

- 生产环境不能设置 `AUTH_DISABLED=true`。
- 不要设置 `UPSTREAM_USD_TO_CNY_RATE`，当前禁止 USD 自动换算 CNY。
- `SUBSCRIPTIONS_ENABLED` 保持 `false`，除非源系统确实启用用户订阅并且管理员已经确认相关字段。
- `DATABASE_URL` 和 Docker 网络名必须从服务器实际环境确认，不能猜测。

### 3.4 确认 Docker 网络

如果 ApiStation 运行在 Docker 中：

```bash
docker network ls
docker inspect YOUR_APISTATION_CONTAINER_NAME
```

把 ApiStation 使用的真实网络名写入：

```dotenv
APISTATION_DOCKER_NETWORK=真实网络名
```

如果 PostgreSQL 在宿主机或独立服务器，`DATABASE_URL` 使用服务器可达的地址，
不一定需要加入 ApiStation Docker 网络。

## 四、首次生产部署

### 4.1 构建镜像

```bash
docker compose -f deploy/docker-compose.example.yml build
```

### 4.2 只读预检

```bash
docker compose -f deploy/docker-compose.example.yml run --rm \
  apistation-finops pnpm preflight
```

预检会检查源表字段、CNY 单位、充值倍率、数据库权限和最近支付订单比例。
预检失败时停止部署，不执行迁移和回填。

### 4.3 执行迁移

```bash
docker compose -f deploy/docker-compose.example.yml run --rm \
  apistation-finops pnpm migrate
```

确认 `001_init.sql`、`002_cny_accounting.sql` 和
`003_reconciliation_snapshots.sql` 已应用。

### 4.4 历史回填

首次回填从源系统游标开始同步用户、账号、用量、充值、退款、兑换码、返利和审计数据。
过程支持中断后继续：

```bash
docker compose -f deploy/docker-compose.example.yml run --rm \
  apistation-finops pnpm backfill
```

低峰期执行。如需限制本次回填轮数：

```bash
docker compose -f deploy/docker-compose.example.yml run --rm \
  -e BACKFILL_MAX_CYCLES=100 \
  apistation-finops pnpm backfill
```

### 4.5 启动服务

```bash
docker compose -f deploy/docker-compose.example.yml up -d --build
```

检查状态和日志：

```bash
docker compose -f deploy/docker-compose.example.yml ps
docker compose -f deploy/docker-compose.example.yml logs -f --tail=200 apistation-finops
```

检查接口：

```bash
curl http://127.0.0.1:8090/health
curl http://127.0.0.1:8090/ready
```

`/health` 表示进程存活；`/ready` 还会检查数据库、`002_cny_accounting`、
`003_reconciliation_snapshots` 和同步状态。

## 五、反向代理

不要把 8090 直接暴露到公网。使用 Nginx、Caddy 或现有网关代理到：

```text
http://127.0.0.1:8090
```

线上至少配置 HTTPS、管理域名访问控制和 sub2api 管理员登录。

### 5.1 原生 PostgreSQL/systemd 服务器

如果 ApiStation、PostgreSQL 和 Redis 是宿主机上的 systemd 服务，而不是 Docker 容器，
FinOps 不需要 Redis，也不需要加入 Docker 网络。使用仓库中的
`deploy/apistation-finops.service` 和 `deploy/finops.env.systemd.example`：

1. 将应用部署到 `/opt/apistation-finops/current`，并由独立的 `finops` 系统账号运行。
2. 将生产环境变量保存为 `/etc/apistation-finops/finops.env`，设置 `HOST=127.0.0.1`、
   `DATABASE_URL` 指向 `127.0.0.1:5432`，并保留 `SUBSCRIPTIONS_ENABLED=false`。
3. 复制 systemd 单元到 `/etc/systemd/system/apistation-finops.service`，执行
   `systemctl daemon-reload && systemctl enable --now apistation-finops`。
4. 通过 `systemctl status apistation-finops` 和
   `curl http://127.0.0.1:8090/ready` 确认服务状态。

此方式仍使用 `finops_app` 最小权限数据库账号，且服务只监听本机回环地址。配置独立管理子域名和 HTTPS
后，再由 Nginx 反向代理到 `127.0.0.1:8090`。

## 六、真实数据验收

上线后先运行 7 天影子观察，不要立即把利润结果作为结算依据。

每天核对：

1. Sub2API 管理员聚合接口与 FinOps 页面在相同时间范围内的请求数、Token 和实际扣费。
2. FinOps 数据库中不再新增请求级用量事实。
3. 充值订单 `amount`、`pay_amount` 和余额入账。
4. 退款、兑换码、返利是否重复计入。
5. 账号采购成本是否登记为 CNY 成本期间。
6. 请求数、Token 数和按日趋势日期是否符合 `Asia/Shanghai`。

采购成本必须登记为账号成本期间，或通过对应 API 写入
`account_cost_periods`。USD 模型目录价只作为 Token 参考展示，不自动生成 CNY 成本。

## 七、日常运维

查看日志：

```bash
docker compose -f deploy/docker-compose.example.yml logs -f --tail=200 apistation-finops
```

重启：

```bash
docker compose -f deploy/docker-compose.example.yml restart apistation-finops
```

升级：

```bash
docker compose -f deploy/docker-compose.example.yml run --rm \
  apistation-finops pnpm preflight
docker compose -f deploy/docker-compose.example.yml run --rm \
  apistation-finops pnpm migrate
docker compose -f deploy/docker-compose.example.yml up -d --build
```

重点备份：

- `finops` Schema。
- `cash_transactions`。
- `account_cost_periods`。
- `reconciliation_runs`。
- `wallet_reconciliation_snapshots`。

FinOps 停止不会影响 ApiStation 的转发、扣费和充值主链路。

FinOps 不允许启用请求级用量同步：

```dotenv
SYNC_USAGE_ENABLED=false
USAGE_DATA_MODE=source_api
```

切换到聚合 API 模式后，可在确认连接目标为独立 FinOps 数据库时清理旧的同步用量：

```bash
pnpm clear:synced-usage
```

该命令只连接 `FINOPS_DATABASE_URL`，并拒绝在与 `SOURCE_DATABASE_URL`
同名的数据库上执行。它不会连接或修改 Sub2API PostgreSQL、Redis。

## 八、常见问题

### `/ready` 返回 503

查看：

```bash
docker compose -f deploy/docker-compose.example.yml logs --tail=200 apistation-finops
```

常见原因是数据库连接失败、迁移未完成、权限脚本未执行，或同步游标处于错误状态。

### 预检提示缺少 `user_subscriptions`

确认：

```dotenv
SUBSCRIPTIONS_ENABLED=false
```

当前按量计费环境不需要该表。只有设置为 `true` 时才需要订阅表及相关字段。

### 预检提示 CNY 单位不匹配

确认：

```dotenv
BASE_CURRENCY=CNY
BILLING_UNIT=CNY
SOURCE_BALANCE_UNIT=CNY
```

同时确认源系统 `users.balance`、`payment_orders.amount` 和管理员聚合接口
`actual_cost` 的业务单位确实为人民币。

### 迁移提示旧账本或旧 `002_dual_ledger`

不要强行执行。先备份旧 Schema，确认旧数据单位，再由数据库管理员重建干净的
`finops` Schema 或制定人工迁移方案。源系统 `public` 表不应被修改。
