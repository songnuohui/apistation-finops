# 供应商评分机制 v2

## 1. 当前机制的问题

当前价格分使用“供应商自身最低活动密钥倍率 / 最近 7 天平均倍率”，不能横向判断哪个供应商更便宜。
此外，连接级平均值会把不同模型、不同密钥和历史倍率混在一起，存在以下问题：

1. 供应商只要长期使用自己的低价密钥，价格分就可能接近 100，即使它比其他供应商更贵。
2. 不同模型的价格、可用性和首字延迟不可直接混合比较。
3. 历史倍率变更会污染当前价格判断。
4. 样本不足时，综合分仍可能看起来很高。
5. 便宜但不可用的供应商可能因为价格权重获得不合理排名。

## 2. 评分单元

最小评分单元调整为：

```text
供应商连接 + 供应商密钥 + 标准化模型
```

模型名称使用 FinOps 的标准化模型名称。别名模型先映射到同一个标准模型，再参与比较。

连接级评分只负责汇总多个模型，不直接混算原始样本。

## 3. 价格数据

### 3.1 数据优先级

同一密钥的当前采购倍率按以下顺序确定：

1. 最近一次成功的只读 billing metadata 探测得到的有效倍率。
2. 供应商门户返回的密钥或分组倍率。
3. 最近 24 小时真实消费记录中的倍率。
4. 无可靠数据时价格维度记为“暂无评分”，不能按默认 1 倍计算。

历史平均倍率只用于趋势展示，不参与当前价格排名。

### 3.2 可比较条件

只有满足以下条件的数据才进入同模型价格比较：

- 连接已启用。
- 密钥状态为可用。
- 该密钥支持目标模型。
- 倍率大于 0。
- 数据在有效期内，门户倍率建议 6 小时，真实探测建议 30 分钟。
- 计费口径一致；无法确认计费口径时不得比较。

### 3.3 模型价格分

同一模型的全局基准价取所有有效供应商中的最低有效采购倍率：

```text
模型价格分 = min(100, 全局最低有效倍率 / 当前有效倍率 * 100)
```

示例：

```text
同模型最低倍率：0.03x
供应商 A：0.03x -> 100 分
供应商 B：0.05x -> 60 分
供应商 C：0.07x -> 42.9 分
```

如果同一模型只有一个可比较供应商，价格分显示“暂无对比”，不能直接给 100 分。

## 4. 质量维度

每个模型分别计算以下分数：

| 维度 | 权重 | 计算原则 |
| --- | ---: | --- |
| 可用性 | 35% | 最近 7 天成功请求 / 可用性样本，使用 Wilson 下界降低小样本虚高 |
| 价格 | 30% | 同模型跨供应商有效采购倍率比较 |
| TTFT | 20% | 以 P50 为主体，P95 长尾追加扣分 |
| 稳定性 | 15% | 失败率、P95/P50 波动和连续失败共同计算 |

### 4.1 硬性限制

- 可用性低于 90%：综合分最高 59。
- 可用性低于 98%：综合分最高 79。
- 最近 24 小时没有成功样本：状态标记为“数据过期”，不参与推荐排序。
- 连续 3 次主动探测失败：状态标记为“不可推荐”。

这样可以避免“便宜但经常不可用”的线路排到前面。

## 5. 连接级汇总

连接总分按模型分数加权汇总：

1. 优先使用 FinOps 最近 7 天真实消费金额作为模型权重。
2. 单个模型权重最高 40%，避免一个高消费模型完全支配连接总分。
3. 没有真实消费时，对已配置的主动探测模型等权计算。
4. 未配置、未探测或不支持的模型不虚构分数，并降低覆盖率与可信度。

```text
连接原始分 = SUM(模型综合分 * 模型权重)
```

## 6. 可信度

可信度独立展示，不直接伪装成质量分：

- 样本数量：达到每模型 30 个有效样本后基本饱和。
- 样本来源：主动真实模型请求权重最高，真实消费次之，门户库存最低。
- 数据新鲜度：越接近当前时间可信度越高。
- 模型覆盖率：已评分模型数 / 需要监控模型数。

推荐排序使用风险调整分：

```text
风险调整分 = 原始综合分 * (0.6 + 0.4 * 可信度)
```

可信度为 100% 时不扣分；可信度为 25% 时只保留原始分的 70%。

## 7. 页面展示

供应商评分列表建议展示：

- 风险调整综合分。
- 原始综合分与可信度。
- 覆盖模型数。
- 当前最低有效倍率。
- 同模型市场基准倍率。
- 价格分。
- 可用性。
- TTFT P50 / P95。
- 连续失败次数。
- 最近成功采样时间。

点击价格分后展示逐模型明细：

```text
模型 | 密钥 | 当前倍率 | 市场最低倍率 | 价格分 | 数据来源 | 采样时间
```

## 8. 实施顺序

### 第一阶段

- 停用供应商自身基准价算法。
- 价格比较改为同模型全局比较。
- 只有一个供应商时价格显示“暂无对比”。
- 页面增加评分公式和数据来源说明。

### 第二阶段

- 增加模型价格快照。
- 使用主动探测目标建立密钥与模型支持关系。
- 增加数据新鲜度、覆盖率和风险调整分。

### 第三阶段

- 根据实际路由结果校准阈值。
- 增加按质量、低价、均衡三种推荐策略。
- 推荐结果仅供 FinOps 展示，不自动修改 Sub2API 或 NewAPI 路由。

## 9. 数据隔离

所有价格快照、模型映射、评分结果和配置均存储在独立 FinOps 数据库。
供应商门户、Sub2API、NewAPI、Redis 和数据库只允许读取，不新增或修改任何上游数据。
