# 管理员登录与会话部署说明

FinOps 使用 sub2api 的现有管理员邮箱和密码登录，不再使用 `ADMIN_TOKEN`，也不会在页面中要求输入管理令牌。

## 安全边界

- FinOps 仅向同一台服务器的 `http://127.0.0.1:8080/api/v1/auth/login` 和相关认证接口发送登录请求。
- sub2api 负责校验密码和 TOTP 双重验证；FinOps 不读取 `public.users.password_hash`，不需要安装 `pgcrypto`，也不为数据库角色增加任何权限。
- 登录后 FinOps 只保存自己签名的 `HttpOnly`、`Secure`、`SameSite=Lax` 会话 Cookie。sub2api 的 access token 和 refresh token 不会返回给浏览器，也不会写入 FinOps 数据库或日志。
- 仅 `role=admin` 且状态正常的 sub2api 用户能够进入 FinOps；普通用户会被拒绝。
- 正常登录会经过 sub2api 自己的认证链路，因此 sub2api 可能保留其常规登录审计记录。这不修改余额、订单、用量、账号凭证或任何业务数据。

## 生产环境变量

在 `/etc/apistation-finops/finops.env` 中配置：

```dotenv
AUTH_DISABLED=false
SUB2API_AUTH_URL=http://127.0.0.1:8080
SUB2API_AUTH_TIMEOUT_MS=10000
SESSION_SECRET=替换为至少32位的高强度随机值
SESSION_TTL_SECONDS=43200
SESSION_COOKIE_SECURE=true
```

生成会话密钥：

```bash
openssl rand -base64 48
```

`SUB2API_AUTH_URL` 必须指向服务器本机的 sub2api，不要填写公网域名。FinOps 只监听 `127.0.0.1:8090`，由 Nginx 以 HTTPS 反向代理；这样 `SESSION_COOKIE_SECURE=true` 才能生效。

## 发布后验证

```bash
systemctl restart apistation-finops
curl -fsS http://127.0.0.1:8090/health
curl -fsS http://127.0.0.1:8090/ready
curl -i http://127.0.0.1:8090/auth/session
```

最后一个请求未登录时应返回 `401`。浏览器打开 `https://finops.apistation.net` 时应自动进入 `/login`；使用 sub2api 管理员邮箱、密码登录。若该管理员启用了 TOTP，页面会继续要求输入 6 位双重验证代码。

不要把 `SESSION_SECRET`、数据库连接串、sub2api 管理员密码或 TOTP 代码写入 Git、聊天记录或 Nginx 配置。
